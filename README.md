# SYSTEM[VERSAGEN] — Investigating Keupstraße

> A digital investigation into the systematic failure surrounding the NSU nail bomb attack of 9 June 2004 on Keupstraße, Cologne.

---

## About the Project

On 9 June 2009, the German Terror Organisation: NSU carried out a bomb attack on the Turkish & Kurdish Community in Keupstraße. What followed was a dramatic failure of the German legal system and a seven-year reversal of perpetrator and victim roles. The project ‘System[Versagen] in Keupstraße’ uses an interactive timeline to highlight these structural missteps by the various involved powers. The levels range from the highest political seats to our society itself. In addition, the website serves to place Mülheim in its historical context. It shows how the creation of the district predestined the later handling of right-wing violence.
The project is deeply inspired by the work of [Forensic Architecture](https://forensic-architecture.org/), whose methodology of spatial and temporal investigation of state violence and institutional misconduct shaped the approach taken here. The design of the website in itself also follows the principles of investigative aesthetics. 

It was developed as a **5th semester university project** at [Code & Context, TH Köln](https://coco.study/), in cooperation with the **[Bildungsinitiative Keupstraße / Initiative Keupstraße ist überall](https://www.keupstrasse-ist-ueberall.de/)**.

## Contributing

Contributions are welcome. Whether that means correcting information, adding translations, improving accessibility, extending the timeline, or refining the codebase.

### How to Contribute

1. **Fork** the repository
2. **Create a branch** for your changes
   ```bash
   git checkout -b feature/your-feature-name
   ```
3. **Make your changes** and commit them with a clear message
   ```bash
   git commit -m "describe what you changed and why"
   ```
4. **Push** to your fork
   ```bash
   git push origin feature/your-feature-name
   ```
5. **Open a Pull Request** and describe your changes

### Guidelines

- Keep commits focused and descriptive
- If you are adding or editing written content, maintain the existing tone: analytical, precise, and grounded in sources
- Translations should stay as close to the original wording as possible
- If you are unsure whether a change is appropriate, open an issue first to discuss it
